### Architecture

```text
            HTTPS :443 (TLS 1.2/1.3 only)
 browser ───────────────▶ ┌─────────┐
                          │  NGINX  │  reverse proxy, TLS termination
                          └────┬────┘
                     FastCGI   │ :9000          private bridge network
                          ┌────▼──────────┐
                          │ WordPress +   │ ◀── volume: wp files
                          │ PHP-FPM       │
                          └────┬──────────┘
                               │ :3306
                          ┌────▼────┐
                          │ MariaDB │ ◀── volume: database
                          └─────────┘
       secrets/ ──(mounted as files)──▶ WordPress, MariaDB
```

### Design choices

- **One process per container.** No `supervisord`: each container's main process is its daemon, so Docker restarts and signals work as intended.
- **Images built from my own Dockerfiles** on `debian:bookworm-slim`. No pre-built images from Docker Hub.
- **Secrets are mounted as files**, never passed as environment variables, which would show up in `docker inspect` and in logs. A setup script generates the credentials on first build, so no keys live in the repository.
- **Only port 443 is exposed.** MariaDB and PHP-FPM can only be reached on the private network.
- **First-run scripts** initialise the database and install WordPress only if they haven't been set up yet, so restarts are idempotent.

**What I learned:** the difference between virtual machines and containers in practice, how to debug containers that fail at startup, and the security habits I now use for every deployment.
