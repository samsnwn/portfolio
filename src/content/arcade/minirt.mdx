## How it works

A `.rt` file describes the scene, one element per line:

```text
A  0.2          255,255,255
C  0,0,-20      0,0,1   70
L  -40,20,-30   0.7     255,255,255
sp 0,0,20.6     12.6    10,0,255
```

The parser stops at the first problem with a clear error: an unknown identifier, a second camera, light or ambient line, a ratio outside 0 to 1, a field of view outside 0 to 180, a radius or height that isn't positive, a malformed colour, and so on. Each pixel then sends a ray from the camera, finds the nearest object it hits, and adds up the ambient light, the diffuse light from the light source unless another object blocks it, and a specular highlight.

The keys act on every object of a type at once: the arrow keys move all the objects, 1 and 2 shrink or grow every sphere and cylinder, and Z, X, C and V rotate all the cylinders or all the planes.

## What I learned

Vector maths becomes intuitive once you have to debug it pixel by pixel. And parsing untrusted input is a real job in its own right.
