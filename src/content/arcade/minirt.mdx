## How it works

A `.rt` file describes the scene, one element per line:

```text
A  0.2              255,255,255
C  -50,0,20  0,0,1  70
L  -40,0,30  0.7    255,255,255
sp 0,0,20.6  12.6   10,0,255
```

The parser rejects anything malformed with a clear error: missing or duplicate camera, out-of-range ratios, normal vectors that aren't normalised, and so on. Each pixel then sends a ray from the camera, finds the nearest object it hits, and adds up the ambient light plus diffuse and specular light from each light source that isn't blocked by another object.

## What I learned

Vector maths becomes intuitive once you have to debug it pixel by pixel. And parsing untrusted input is a real job in its own right.
