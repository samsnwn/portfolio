# M2: push_swap and fract-ol Playable Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `/play/push-swap` and `/play/fractol` playable in the browser. Both run Samuel's original 42 C code, compiled to WebAssembly with Emscripten.

**Architecture:**
- **Private repo `portfolio-native`** (`~/dev/portfolio-native`). It holds untouched copies of the C sources plus web glue: a push_swap game API in C and a fake MiniLibX that draws into a `<canvas>`. It builds them with Emscripten inside Docker and installs `.mjs` and `.wasm` files into the site's `public/native/`.
- **Site.** It loads those modules at runtime from two React islands, `PushSwapGame` and `FractolGame`.
- **fract-ol's event loop.** `mlx_loop` stays alive with Asyncify. It polls a JS event queue, so `main`'s stack (`t_app app`) stays valid and every hook runs from C, exactly as on Linux.

**Tech Stack:**
- Emscripten, using the `emscripten/emsdk` Docker image pinned to an exact tag. Builds with `-O3`, `MODULARIZE`, `EXPORT_ES6` and `ASYNCIFY` (fract-ol only).
- Node's built-in `node:test` for the native repo.
- The existing Astro, React, Vitest and Playwright setup for the site.

**Spec:** `docs/SPEC.md` (§4A Arcade, §5, §7, milestone M2 in §8) and `docs/adr/0001-real-c-via-wasm.md`.

## Global Constraints

- **The original C is never edited.**
  - `vendor/` holds byte-identical copies of `~/dev/42/rank2/push_swap` and `~/dev/42/rank2/fractol`. A test enforces this.
  - Everything web-specific lives in `api/`, `shim/` and the build flags.
  - If a patch ever becomes unavoidable, it goes in `patches/*.diff` and the deviation is recorded in the ledger.
- **The C source stays private.** `portfolio-native` is a **private** GitHub repo, and only the compiled `.mjs` and `.wasm` files reach the public site repo.
- **Samuel approves anything outward-facing.**
  - Creating the GitHub repo needs his approval.
  - **Pushing the site's `main` branch auto-deploys to samuelcglantz.com.** Work on the branch `m2-games`, and never push `main` or deploy without Samuel's explicit go-ahead.
- **Same origin only.** `/play/*` sends `COEP: require-corp`, so every asset (`.mjs`, `.wasm`) is served from the site itself under `/native/...`.
- **The Mission Briefing stays first** on each play page and is readable even if the game fails to load.
- **Sound** stays muted. M2 adds no audio.
- **Mobile:** both games must be playable with touch alone, using on-screen controls. No keyboard required.
- **Reduced motion:** no auto-animated replays. Show the final state, with manual stepping.
- **Copy:** each game page says it is "my original C code, compiled to WebAssembly".

### Task 2: push_swap game API in C

**Files:**
- Create: `api/push_swap_api.c`, `tests/pushswap-api.test.mjs`
- Modify: `Makefile` (target `pushswap`, plus `install`)

**Interfaces:**
- **Build:** `make pushswap` builds `build/pushswap.mjs` and `.wasm` from push_swap's `src/` *without* `main.c`, plus `api/push_swap_api.c` and libft.
  - `EXPORTED_FUNCTIONS`: `_ps_load,_ps_apply,_ps_can,_ps_size,_ps_copy,_ps_is_sorted,_ps_solve,_malloc,_free`
  - `EXPORTED_RUNTIME_METHODS`: `HEAP32`
- **C API** (all state is file-static in `push_swap_api.c`, and stacks are freed on every `ps_load`). Operation codes: `0 sa, 1 sb, 2 ss, 3 pa, 4 pb, 5 ra, 6 rb, 7 rr, 8 rra, 9 rrb, 10 rrr`.
  - `int ps_load(const int *nums, int n)` resets both stacks to `a = nums`, `b = empty`. It returns 0, or -1 if `n < 1`.
  - `int ps_can(int op)` returns 1 if the operation changes something. Swaps need 2 or more elements on their stack(s). Pushes need a non-empty source. Rotations need 2 or more elements. For `ss`, `rr` and `rrr`, at least one side must qualify.
  - `int ps_apply(int op)` calls Samuel's original `sa`…`rrr` (`pb` is called as `pb(&b, &a)`). It returns 1 if applied and 0 if `!ps_can(op)`, in which case nothing is called.
  - `int ps_size(int which)` and `void ps_copy(int which, int *out)`: `which` is 0 for `a` and 1 for `b`, copied from top to bottom.
  - `int ps_is_sorted(void)` returns 1 when `b` is empty and `stack_sorted(a)` is true.
  - `int ps_solve(const int *nums, int n)` builds fresh private stacks from `nums`, calls the original `sort_stack`, frees them, and returns 0. The operations reach JS through `print`, one per line. It never touches the game stacks.
- **`make install SITE=../portfolio`** copies `build/pushswap.{mjs,wasm}` to `$SITE/public/native/push-swap/` and `build/fractol.{mjs,wasm}` (Task 3) to `$SITE/public/native/fractol/`.

  - `apply runs the original ops`: after `ps_load([2,1,3])` and `ps_apply(0 /*sa*/)`, `a = [1,2,3]`, and `ps_is_sorted() === 1`.
  - `impossible moves are refused, not crashed`: after `ps_load([1])`, `ps_can(3 /*pa*/) === 0`, `ps_apply(3) === 0`, `ps_apply(0) === 0`, and `a` is still `[1]`.

### Task 3: Fake MiniLibX and fract-ol as WebAssembly

**Files:**
- Create: `shim/minilibx-linux/mlx.h`, `shim/mlx/mlx.h`, `shim/mlx/mlx_web.c`, `shim/mlx/mlx_web.js` (an Emscripten `--js-library`), `shim/mlx/keymap.mjs`, `shim/X11/X.h`, `tests/mlx-keymap.test.mjs`, `tests/fractol-build.test.mjs`
- Modify: `Makefile` (target `fractol`)

**Interfaces:**
- **`shim/X11/X.h`** defines exactly what fract-ol uses, with X11's real values: `KeyPress 2`, `ButtonPress 4`, `DestroyNotify 17`, `KeyPressMask (1L<<0)`, `ButtonPressMask (1L<<2)`, `StructureNotifyMask (1L<<17)`, `Button4 4`, `Button5 5`.
- **`shim/mlx/mlx.h`** has minilibx-linux's signatures for: `mlx_init`, `mlx_new_window`, `mlx_new_image`, `mlx_get_data_addr`, `mlx_put_image_to_window`, `mlx_hook`, `mlx_loop`, `mlx_destroy_image`, `mlx_destroy_window`, `mlx_destroy_display`.
- **`mlx_web.c` behaviour:**
  - `mlx_new_image` mallocs `w*h*4` bytes, and `mlx_get_data_addr` returns `bpp=32`, `size_line=w*4`, `endian=0`.
  - `mlx_put_image_to_window` calls the JS `mlxweb_blit(ptr, w, h)`. In the browser that converts BGRX to RGBA (alpha 255) into the canvas's `ImageData`.
  - `mlx_hook` stores up to three hooks, keyed by event number.
  - `mlx_loop` runs forever: on each pass it drains `mlxweb_poll(&type, &a, &b, &c)` and dispatches `KeyPress` as `hook(keysym, param)`, `ButtonPress` as `hook(button, x, y, param)` and `DestroyNotify` as `hook(param)`. Then it calls `emscripten_sleep(16)`.
  - The destroy functions are no-ops that free the image buffer.
- **`keymap.mjs`** is pure and shared by the JS library and the tests:
  - `keyToKeysym(key: string): number | null` maps `ArrowLeft` to 65361, `ArrowRight` 65363, `ArrowUp` 65362, `ArrowDown` 65364, `+` and `=` to 65451, `-` to 65453, `Escape` to 65307. Anything else is `null`.
  - `wheelToButton(deltaY: number): 4 | 5 | null` returns 4 when `deltaY < 0` and 5 when `deltaY > 0`.
  - `bgrxToRgba(src: Uint8Array, dst: Uint8ClampedArray): void`.
- **The JS side exposes `Module.mlxweb`:**
  - `push(type: 2|4|17, a?: number, b?: number, c?: number)`, the queue the site feeds.
  - `canvas: HTMLCanvasElement`, set by the site before `callMain`.
- **Build:** `make fractol` gives `build/fractol.{mjs,wasm}`, with flags `-O3 -sMODULARIZE -sEXPORT_ES6 -sENVIRONMENT=web,node -sASYNCIFY -sEXIT_RUNTIME=1 -sINVOKE_RUN=0 -sALLOW_MEMORY_GROWTH -Ishim/mlx -Ishim -Ivendor/fractol/libft/include --js-library shim/mlx/mlx_web.js`.
  - fract-ol's `#include "./minilibx-linux/mlx.h"` resolves through the `-Ishim` search path to **`shim/minilibx-linux/mlx.h`**, which is a one-line `#include "../mlx/mlx.h"`. No vendored file is edited.
